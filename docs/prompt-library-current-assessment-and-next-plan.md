# 提示词库当前评估与下一步

更新时间：2026-06-09

适用范围：`D:\gpt_image_playground-main`

## 1. 当前判断

提示词库当前已经够支撑标准版平台前台：

- 官方模板能快速起图
- 我的模板和最近使用能形成个人沉淀
- 工作台草稿保存路径已经成立

所以当前重点不再是“继续大量加模板”，而是：

1. 保持前台工具页足够轻。
2. 把现有模板字段收口好。
3. 为后台管理和服务端化做准备。

## 2. 当前前台方向

提示词库前台应继续遵守这些方向：

- 默认服务于“快速挑选并带回工作台”
- 保留`官方模板 / 我的模板 / 最近使用`
- 保留快速分组：`全部 / 海报插画 / 人像摄影 / 产品品牌 / 空间信息`
- 不把 tags 作为页面级信息层
- 不恢复右侧大详情区
- 不把页面做成说明型内容库

## 3. 当前模板数据状态

`src/lib/promptLibrary.ts` 已经具备后续可迁移的数据雏形，核心字段包括：

- `id`
- `title`
- `summary`
- `category`
- `ratio`
- `tags`
- `prompt`
- `negativePrompt`
- `guidance`
- `featured`
- `templateType`
- `sourceName`
- `sourceAuthor`
- `sourceUrl`
- `license`

这说明当前模板数据已经不是纯占位 UI，而是可继续演化的前端草模。

## 4. 当前阶段不建议做的事

短期内不建议继续：

- 无上限扩前端静态模板
- 做复杂筛选系统
- 加入行业化模板体系
- 把提示词库做成内容阅读页

原因很简单：

- 当前前台更需要操作效率，不需要信息层膨胀。
- 继续硬编码扩库，只会增加后续迁移成本。

## 5. 下一步建议

提示词库的下一步应按这个顺序推进：

1. 继续前台轻量收口，确保模板页更像工具面板。
2. 产出 `prompt_templates` schema 草案。
3. 产出模板后台管理 API 草案。
4. 产出后台信息架构。
5. 再决定后续扩库是否从后台导入。

## 6. 和主路线的关系

提示词库当前不应单独抢主线。它在当前项目里的角色是：

- 前台创作流程的高频辅助工具
- 后续模板后台化的起点

当前默认优先级仍然是：

1. 前台创作流程收口
2. PostgreSQL 统一账号 / 余额 / 订单 / 扣点后端
3. 独立管理后台
4. 模板后台化
