# 当前产品评估与开发主线

更新时间：2026-06-09

适用范围：`D:\gpt_image_playground-main`

## 1. 当前主判断

当前项目的唯一主线应明确为：

- 当前项目按`标准版 / 商业化图像创作平台`推进。
- 前台、后台、计费、Gateway、模型可用线路、模板治理都服务同一套平台主线。
- 数据库主线统一为自托管 Node API + PostgreSQL；旧 Cloudflare D1、Vite mock D1、JSON 持久化代码已从当前主线移除。

这意味着后续默认优先级是：

1. 统一前后台数据源，保证账号、余额、充值码、后台用户管理都读写 PostgreSQL。
2. 保持前台创作主流程简洁可用。
3. 按轻量后台优先级推进模型、线路、充值码、用户与提示词模板管理。
4. 最后再扩更复杂的运营、Agent 深整合和内容治理能力。

如果旧文档与本文件冲突，以本文件为准。

## 2. 当前前台已形成的方向

### 2.1 工作台

当前工作台已经具备标准版平台前台的核心骨架：

- 主提示词输入
- 负面提示词
- 参考图上传 / 粘贴 / 拖拽
- 多参考图与 `@` 引用
- 比例、质量、格式、输出数量控制
- 模型 SKU 选择
- 提示词优化器
- 任务重试、复用、编辑输出
- 结果卡片、详情、大图查看、下载

当前前台体验上的正确方向是：

- 首页优先输入、生成、当前结果
- 次要资产区降权，不做大段说明
- 不再把 API 配置当作普通用户叙事中心

### 2.2 提示词库

当前提示词库已经从演示页进入“可复用工具页”阶段：

- 官方模板可直接套用
- 我的模板、最近使用已具备个人沉淀逻辑
- 工作台草稿可保存为个人模板

已确认的界面方向：

- 只保留快速分组，不扩成信息密集型内容页
- 不把 tags 当作页面级信息层
- 不恢复右侧大详情面板
- 优先“找模板并带回工作台”，不是“阅读模板说明”

### 2.3 登录 / 注册

当前账号入口已经进入真实后端化阶段，产品方向明确：

- 第一版采用邮箱注册 / 邮箱登录 / 邮箱找回
- 不做手机号注册
- 不做短信验证码登录
- 登录后回原页继续操作

### 2.4 作品与沉淀

当前已具备：

- 作品库
- 收藏
- 本地任务记录
- 结果复用

但目前仍然是前台本地沉淀，不应被误判为真实多端资产系统。

### 2.5 灵感广场

灵感广场作为后续公开展示与内容沉淀模块规划，不等同于现有私链分享，也不按重社区方向推进。

已确认方向：

- 定位为 `编辑精选型展示层`，不是点赞、评论、关注、私信式社区。
- `1K` 作品不能发布，发布门槛以服务端最终成品宽高为准，长边至少 `2048`。
- 私链分享和广场发布必须分层，普通分享使用 `manual`，广场公开分享使用 `inspiration_public`。
- 后台采用 `AI 自动初审 + 人工抽查`，AI 负责质量备注、风险分流和精选建议，人工只处理重点队列。

详细方案见：

- `docs/inspiration-square-development-plan.md`

## 3. 当前必须明确的边界

### 3.1 前后台必须使用统一数据源

当前这些能力必须统一走 Node API + PostgreSQL：

- 登录态
- 余额
- 充值
- 扣点
- 订单
- 作品同步

本地预览的 `/api/*` 应代理到 PostgreSQL 后端，避免前台和后台看到两套用户数据。

### 3.2 管理后台必须独立，不混进前台叙事

后台是当前平台主线的一部分，但不应让普通用户前台被“后台能力”“运维能力”“线路管理能力”稀释。

后台规划请单独看：

- `docs/admin-backend-development-plan.md`

### 3.3 旧计划文档只保留为历史参考

旧路线、旧阶段边界、旧 checkpoint 仍有背景价值，但不再作为当前执行基线。

## 4. 当前最重要的问题

当前真正需要继续解决的不是“再加功能”，而是下面几件事：

1. 前台页面仍有少量说明感过重、阅读层级偏厚的问题。
2. 账号、余额、订单、扣点仍未切换到真实后端模型。
3. 旧文档仍容易让人误读当前主线。
4. 模板库已经够用，下一步应转向后台化准备，而不是继续前端硬编码扩库。
5. 灵感广场已进入方案沉淀阶段，实施前按独立开发方案推进，不挤占当前账号、计费、后台主线。

## 5. 当前执行顺序

### Phase A：统一后端数据源与前台主流程收口

目标：把前台账号、余额、充值码、后台用户管理统一到 PostgreSQL，同时保持前台创作界面紧凑、清楚、可继续迭代。

当前建议继续做：

1. 全页视角审视并压缩说明层。
2. 统一登录、余额、结果、模板等入口的轻量文案。
3. 校对 guest / no-balance / ready 三条主路径。
4. 做一次整体构建与关键页面验证。

当前不做：

- 不扩行业化模板
- 不做复杂营销页
- 不大改 Agent 交互主线
- 不把后台功能显性带进前台导航

### Phase B：真实后端基础

目标：把 mock 的账号与计费替换成真实服务端能力。

建议顺序：

1. 用户表、会话、邮箱注册登录
2. 邮箱验证、找回密码
3. 服务端账户余额
4. 充值订单
5. 扣点流水
6. 服务端任务记录
7. 前台改为读取服务端可信状态

### Phase C：管理后台

目标：给运营、客服、财务、运维一套独立后台。

详细方案见：

- `docs/admin-backend-development-plan.md`

### Phase D：模板后台化准备

目标：把官方提示词模板从前端静态数据逐步迁到可治理结构。

建议顺序：

1. `prompt_templates` schema 草案
2. 模板管理 API 草案
3. 模板后台信息架构
4. 再决定后续扩库是否走后台导入

### Phase E：灵感广场与 AI 运营台

目标：在安全结果分享能力之上，新增高质量公开作品展示层，并用 AI 自动初审降低后台人工成本。

建议顺序：

1. 先完成 `manual / inspiration_public` 分享用途分层。
2. 新增 `inspiration_posts` 数据表和发布资格接口。
3. 落地 `2K+ / auto_pass / 非极端比例 / 文件可读` 的硬门槛。
4. 做 `/inspiration` 首页、详情页和结果详情发布入口。
5. 做灵感广场运营台基础队列。
6. 接入 AI 质检与自动分流，再扩展精选专题和数据统计。

## 6. 当前推荐立即推进

推荐现在继续做：

1. 以前后台统一数据源为准，继续做整体页面修正。
2. 统一当前主计划文档，避免旧计划继续竞争。
3. 保持后台规划单独存在，不混入前台普通用户叙事。
4. 持续推进真实账号、余额、充值码与计费后端。
