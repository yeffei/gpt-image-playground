# 作品库存储与保留策略

更新时间：2026-07-04  
适用范围：`D:\gpt_image_playground-main`

## 1. 当前定论

这版不再采用“作品库长期保留”的口径，正式改为“有限保留 + 快速回收”：

- 正式作品仍上传到服务端保存，不放在 PostgreSQL 大字段里
- 普通账号作品库默认只保留最近 `100` 张正式作品
- 超出 `100` 张后，最旧且未被分享 / 未被灵感广场引用的作品，会自动移入回收站
- 回收站保留 `7` 天，到期后清理底层文件和数据库状态
- 灵感广场帖子、未撤销分享等仍在引用的作品，不参与自动挤出

这套规则的目标只有一个：尽量缩短占用服务器空间的时间，同时保留基本可恢复能力。

## 2. 图片实际保存在哪里

当前真实实现：

- 图片二进制默认落盘到 `server/storage/generated-images`
- 访问路径默认通过 `/api/generated-images/...`
- 数据库 `generation_task_outputs` 保存：
  - `storage_provider`
  - `storage_key`
  - `public_url`
  - `mime_type`
  - `byte_size`
  - `width`
  - `height`

也就是说：

- PostgreSQL 保存元数据和关系
- 图片文件本体保存在服务端文件存储

后续如果迁移到 `S3 / R2 / OSS / MinIO`，仍然沿用 `storage_provider + storage_key` 这套真相。

## 3. 为什么不再做长期保留

用户 `213321@qq.com` 在 `2026-07-04` 的快照里已经有 `105` 张正式作品，约 `221.5 MB`。

如果继续按“长期保留”理解，会带来几个直接问题：

- 每个活跃账号的历史图会一直累积
- 本地磁盘或对象存储会持续线性增长
- 后面再补容量策略时，需要做一次更重的回收和口径切换

所以现在直接把规则收紧为：

- 作品库不是永久档案馆
- 作品库更像“最近可用资产池”
- 超出上限的旧作品先进入 `7` 天回收站，再物理清理

## 4. 各类资产保留规则

| 资产类型 | 当前策略 |
| --- | --- |
| 用户正式作品 | 只保留最近 `100` 张 active 输出 |
| 超出上限的旧作品 | 自动移入回收站 |
| 用户主动删除的作品 | 直接进入回收站 |
| 回收站作品 | 保留 `7` 天 |
| 回收站到期且无引用作品 | 清理底层文件 |
| 失败 / 超时 / 取消任务记录 | 建议保留 `90` 天用于排障 |
| 普通分享记录 | 可独立过期，不决定作品本体是否立即删除 |
| 灵感广场公开作品 | 只要仍被公开内容引用，就先不自动挤出 |

## 5. 当前实现口径

已落地的核心行为：

- `generation_task_outputs` 增加软删除与清理字段
- 用户删除正式作品时，不再直接硬删，先进入回收站
- 回收站恢复入口已接到 output 级接口
- 回收站保留期已经收紧为 `7` 天
- 清理脚本会按 `purge_after` 扫描，并跳过仍被分享 / 灵感广场引用的输出
- 服务端已接入回收站清理调度器，默认会按间隔自动执行
- 新增作品写入后，会检查用户 active 输出数量；超过 `100` 张时，自动把最旧的可回收作品转入回收站
- 当 active 作品已达 `100` 张时，回收站作品不允许直接恢复，避免再次撑大作品库

调度器环境变量：

- `TRASHED_OUTPUT_CLEANUP_ENABLED`
- `TRASHED_OUTPUT_CLEANUP_LIMIT`
- `TRASHED_OUTPUT_CLEANUP_INTERVAL_MINUTES`
- `TRASHED_OUTPUT_CLEANUP_RUN_ON_STARTUP`

## 6. 对用户的前台语义

前台应该统一按下面这套理解：

- 作品库默认保留最近 `100` 张正式作品
- 删除后进入回收站，可在 `7` 天内恢复
- 回收站中的作品到期会永久清理
- 已分享或已进入灵感广场的作品，在解除引用前不会被自动挤出

不要再对用户承诺“默认长期保存”或“永久保存”。

## 7. 对现有账号的影响

对已经超过 `100` 张的账号：

- 新规则会在后续新增正式输出时开始生效
- 旧作品会优先按“最旧、未分享、未进广场”的顺序进入回收站
- 已在回收站中的作品仍只保留 `7` 天

如果需要一次性回收历史超额作品，可以再补后台运维脚本；但这一步不应隐式对真实用户数据直接执行。

## 8. 后续建议

- 后台补一个“各用户 active 作品数 / 回收站数 / 总字节数”统计面板
- 后台补一个手动执行的“超额作品回收”运维脚本
- 如果后面做套餐，再把 `100 张`、`7 天` 扩展成套餐配置项
