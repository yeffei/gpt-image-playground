# 提示词库来源评估与引入标准

更新时间：2026-06-03

适用范围：`D:\gpt_image_playground-main`

## 1. 目的

本标准用于评估外部提示词库是否适合引入本项目的：

- 官方模板
- 提示词库
- 精品案例库
- 后续结构化模板系统

目标不是追求条目数量，而是优先引入：

- 成图完成度高
- 可复用性强
- 普通用户可直接套用
- 可持续维护
- 许可边界清晰

后续新增任何外部提示词库，默认先按本标准评估，再决定是否引入。

## 2. 引入原则

### 2.1 精品优先，不凑数

宁可少量高质量模板，也不导入大量普通案例。

不以“仓库星标多”“案例数量多”作为主要判断依据。

### 2.2 先看可复用，不只看好看

单张图再惊艳，如果 prompt 只能复现那一张图，不能优先引入。

优先引入可以跨主题、跨主体、跨场景复用的方法型 prompt。

### 2.3 先看产品适配，不只看作者能力

适合作者本人使用的复杂 prompt，不等于适合普通用户在站内一键套用。

引入时优先考虑：

- 用户是否容易理解
- 是否容易替换主体和场景
- 是否容易得到稳定输出

### 2.4 先看许可，再看内容

许可、来源、署名、商业使用边界不清晰的内容，不进入正式官方模板库。

如内容质量很高但许可边界不明确，只能作为内部研究参考，不直接搬运上线。

## 3. 评估维度

每个候选来源按以下 6 个维度评估。

### 3.1 内容质量

看点：

- 成图是否有明显完成度
- 是否有一致审美和控制力
- 是否存在大量普通随手图
- 是否有清晰的精品比例

淘汰信号：

- 靠数量堆积
- 大量重复题材
- 示例图质量波动过大

### 3.2 Prompt 可复用性

看点：

- prompt 是否能替换主体继续用
- prompt 是否具有稳定结构
- 是否能抽象成模板骨架
- 是否包含有价值的约束语法

淘汰信号：

- 只能绑定某张特定图
- 主要是随手描述，没有结构
- 对普通用户几乎不可复现

### 3.3 结构化程度

看点：

- 是否有标题
- 是否有分类
- 是否有说明文案
- 是否有完整 prompt
- 是否有示例图
- 是否有作者 / 来源字段

优先级：

- 有“标题 + 示例图 + 完整 prompt + 简介”的内容，最适合 V1 落库
- 有模板骨架、变量槽位、分类法的内容，适合后续结构化升级

### 3.4 产品适配度

看点：

- 是否适合做“官方模板”
- 是否适合做“展示型案例”
- 是否适合做“可编辑模板”
- 是否适合进入“提示词优化器联动”

淘汰信号：

- 内容过度依赖特定模型暗知识
- 内容过度依赖作者手工后处理
- 内容不适合普通用户直接使用

### 3.5 许可与来源风险

必须核对：

- 仓库 license
- README 中是否有第三方内容说明
- 是否要求单独署名
- 是否提示商业使用需额外确认

处理原则：

- `可直接引入`：许可清晰，且内容权属说明无明显冲突
- `可部分引入`：仓库整体许可清晰，但部分内容可能来自第三方，需要精选和标注
- `仅研究参考`：许可模糊，或 README 明确提示第三方内容需单独确认

### 3.6 维护成本

看点：

- 是否容易转成我们自己的字段结构
- 是否容易做分类、搜索、推荐
- 是否容易后续人工精选
- 是否容易持续扩充

淘汰信号：

- 目录混乱
- 内容强依赖原仓库运行逻辑
- 不易拆成单条模板

## 4. 评分规则

每个来源按 5 分制评分：

- `5`：非常适合
- `4`：适合
- `3`：可部分采用
- `2`：仅少量参考
- `1`：不建议引入

建议按以下权重综合判断：

- 内容质量：30%
- Prompt 可复用性：25%
- 结构化程度：15%
- 产品适配度：15%
- 许可与来源风险：10%
- 维护成本：5%

最终分级：

- `A`：可作为主来源
- `B`：可作为辅助来源
- `C`：只做方法参考
- `D`：不进入正式引入范围

## 5. 引入决策类型

评估后只能进入以下 4 类之一：

### 5.1 主来源

适用：

- 内容质量高
- 结构清晰
- 可直接拆成单条模板
- 许可边界可控

用途：

- 直接作为官方模板库首批内容来源

### 5.2 辅助来源

适用：

- 有部分高质量内容
- 适合补充题材或风格
- 不适合整库导入

用途：

- 精选少量案例补充主库

### 5.3 方法参考

适用：

- 强项在分类法、模板法、prompt 工程方法
- 不适合整库搬运

用途：

- 用于指导我们的模板设计、标签体系和提示词优化器

### 5.4 内部研究

适用：

- 内容可能有价值
- 但许可、来源、结构或质量不满足正式引入标准

用途：

- 仅团队内部学习，不入正式产品库

## 6. 落库字段标准

如果某来源通过评估，导入前应尽量映射为统一字段：

- `id`
- `title`
- `summary`
- `category`
- `tags`
- `prompt`
- `negativePrompt`
- `exampleImage`
- `sourceName`
- `sourceUrl`
- `sourceAuthor`
- `license`
- `qualityTier`
- `templateType`
- `isFeatured`
- `reviewStatus`

其中：

- `qualityTier`：`featured / standard / research`
- `templateType`：`showcase / reusable / structured`
- `reviewStatus`：`pending / approved / rejected`

## 7. 首批引入偏好

结合当前产品阶段，V1 优先引入以下类型：

- 海报感强、完成度高的展示型案例
- 普通用户一眼能理解的一键套用模板
- 可替换主体、材质、场景的复用型 prompt
- 适合和提示词优化器联动的结构化骨架

V1 暂不优先：

- 过度行业化模板
- 强依赖复杂后处理的案例
- 仅适合高级作者的小众 prompt
- 权属不清晰的拼贴型内容

## 8. 对当前两个候选来源的初步结论

### 8.1 `ImgEdify/Awesome-GPT4o-Image-Prompts`

结论：

- 归类为：`主来源候选`

原因：

- 单条内容更接近可直接落库的官方模板
- 标题、示例图、完整 prompt 结构更适合 V1
- 适合精选一批高完成度案例作为前台内容基础

注意：

- 仍需人工精选，不做整库无差别导入
- 优先保留来源、作者和 license 信息

### 8.2 `freestylefly/awesome-gpt-image-2`

结论：

- 归类为：`方法参考 + 辅助来源候选`

原因：

- 强项在模板体系、分类法、Prompt as Code 思路
- 更适合提炼精品模板骨架，而不是整库直接搬运
- 对我们后续做结构化模板库、提示词优化器联动很有价值

注意：

- 不建议整库直搬
- 若引用具体内容，应先核对其第三方来源和商用边界

## 9. 后续执行方式

以后新增外部提示词库时，默认按以下步骤处理：

1. 先做来源评估，不先导入。
2. 先判定是主来源、辅助来源、方法参考还是内部研究。
3. 只对通过评估的来源做人工精选。
4. 先落“精品子集”，不一次性全量搬运。
5. 导入时统一字段、统一标签、统一来源标注。

本标准优先于临时主观判断，用于减少后续提示词库扩充时的反复讨论成本。
