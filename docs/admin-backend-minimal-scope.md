# 后台最小范围规则

更新时间：2026-06-08

适用范围：`D:\gpt_image_playground-main`

## 1. 目的

本文件用于修正后台设计复杂度。后续后台实现优先按本文件执行；旧文档里更复杂的统计、诊断、审批、批量运营、增长运营、复杂 CMS 能力，除非用户重新明确要求，否则都视为后续扩展，不进入第一版。

后台第一版要解决三个核心问题：

1. 官方提示词模板怎么搬、怎么审、怎么手工添加。
2. 中转站线路、生图模型和基础线路策略怎么由后台维护。
3. 充值码怎么按批次生成、导出、兑换和记录。

## 2. 提示词模板后台

只保留两个入口。

### 2.1 自动搬运来源

管理员输入一个网址或 GitHub 仓库链接。

后台流程：

1. 拉取来源内容。
2. 下载关联图片并转成本地文件。
3. 按提示词库分类规则筛选候选内容。
4. 只把候选精品放入人工审核列表。
5. 管理员人工审核后，批准的条目才进入网站官方提示词库。

第一版不做：

- 复杂 CMS。
- 多级审批流。
- 模板版本 diff。
- 用户评论管理。
- A/B 实验。
- 大型模板数据分析。
- 复杂批量运营面板。

### 2.2 手工添加

后台支持管理员每次手工添加一个官方提示词模板。

必填内容：

- 标题。
- 分类。
- 提示词正文。
- 本地图片或图片来源。

可选内容：

- 标签。
- 来源链接。
- 备注。

手工添加不需要复杂批量页。保存后可直接进入人工审核或直接发布，具体实现以后端默认规则为准。

## 3. 网关和模型后台

后台做配置管理和基础线路策略管理。策略可以进后台，但必须保持简单、可理解，不做复杂诊断面板。

### 3.1 中转站路线

后台支持手工管理中转站线路：

- 新增线路。
- 编辑线路。
- 删除线路。
- 启用 / 停用线路。
- 配置线路对应的接口地址、密钥引用、上游模型名。

普通后台页面不展示复杂诊断字段，例如线路健康、冷却状态、运维强制切换、线路选择细节。需要排障时可以保留在运维文档或内部诊断接口，不作为第一版后台主功能。

### 3.2 生图模型

后台支持管理可选生图模型。

第一批常见模型：

- `gpt image 2`
- `gemini`
- `grok`

后台允许以后新增第 4、5、6 个模型。

每个模型需要能绑定可用中转站线路。

### 3.3 基础线路策略

后台可以配置基础线路策略：

- 每个模型绑定哪些线路。
- 每个模型下的线路顺序，优先尝试哪一条。
- 每个模型下的分流比例，用于多条线路可用时的分配。
- 每个模型下的等待秒数。
- 失败后是否自动尝试下一条可用线路。

第一版不做：

- 复杂线路健康看板。
- 冷却明细管理。
- 运维强制切换面板。
- 线路选择细节展示。
- 让管理员直接编辑后端评分公式。

也就是说，后台可以管策略参数，但后端仍负责执行策略和兜底逻辑。

## 4. 充值码后台

充值码后台只服务第三方店铺卡密库存。

后台功能：

1. 选择面额：`30 点`、`100 点`、`300 点`。
2. 输入生成数量。
3. 系统自动生成批次编号。
4. 系统自动生成兑换码编号。
5. 按批次导出 TXT 文件，一行一个完整兑换码。
6. 管理充值码状态。
7. 查看兑换记录。

第一版不做：

- 导入第三方已经生成的码。
- 手工指定外部订单号。
- 复杂渠道对账。
- 复杂优惠券系统。
- 站内支付回调。

兑换规则：

- 只有 `active` 兑换码可以兑换。
- 已兑换码不能二次兑换。
- 已过期码不能兑换。
- 已停用码不能兑换。
- 兑换成功必须记录用户、时间、面额、余额变化和关联充值码。

## 5. 后续实现优先级

第一阶段：

1. 简化充值码批次生成、TXT 导出和兑换记录。
2. 简化中转站路线、模型 CRUD 和基础线路策略配置。
3. 简化提示词模板的手工添加。

第二阶段：

1. 实现网址 / GitHub 来源自动搬运。
2. 图片下载到本地。
3. 候选提示词筛选。
4. 人工审核后发布。

第三阶段：

1. 仅在确实需要时增加诊断、统计、批量运营能力。
2. 每新增一个复杂功能前，先确认它是否服务当前后台的核心流程。
