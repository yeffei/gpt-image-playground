# 官方模板后台页面信息架构

更新时间：2026-06-03

适用范围：`D:\gpt_image_playground-main`

## 0. 当前有效简化范围

2026-06-08 起，提示词模板后台第一版按 `docs/admin-backend-minimal-scope.md` 执行。本文后续较复杂的列表、批量、推荐、排序、统计和批次页设计只作为历史参考，不作为当前实现范围。

当前只保留两个入口：

1. 输入一个网址或 GitHub 仓库链接，后台自动搬运内容，图片下载成本地文件，按提示词库规则筛选候选精品，最后人工审核，审核通过后才进入网站。
2. 后台人工手工添加，每次添加一个官方提示词模板。

第一版不做复杂 CMS、不做多级审批、不做模板数据分析大盘、不做评论管理、不做 A/B 实验。

## 1. 目的

本文件用于定义“官方模板提示词库后台管理”的页面信息架构。

目标不是立刻做 UI，而是先明确：

- 后台应该有哪些页面
- 每个页面负责什么
- 页面之间怎么跳转
- 第一版哪些信息必须出现

本文件服务于：

1. 后台系统统一开发时的页面蓝图
2. 模板后台 API 的消费方定义
3. 前台模板服务端化前的管理面收口

## 2. 设计边界

第一版后台只管理：

- 官方模板

第一版不管理：

- 我的模板
- 最近使用
- 用户收藏列表
- 模板评论
- 复杂审批流

第一版目标不是做复杂 CMS，而是做“来源搬运 + 人工审核 + 单条手工添加”的轻量后台。

## 3. 后台模块位置

建议放在管理后台主导航中的：

- `模板管理`

下设页面建议：

1. 模板列表
2. 新建模板
3. 模板详情 / 编辑
4. 批量操作视图
5. 导入批次记录

如果第一版要更克制，也可以先收成：

1. 模板列表
2. 模板编辑页
3. 导入批次页

## 4. 页面结构总览

建议页面层级：

### 4.1 模板列表页

路径建议：

- `/admin/templates`

用途：

- 查看全部官方模板
- 按条件筛选
- 快速上下架
- 快速看来源、类型、排序、推荐状态
- 进入详情 / 编辑

### 4.2 新建模板页

路径建议：

- `/admin/templates/new`

用途：

- 手工新增模板
- 录入来源和标签
- 先存为草稿

### 4.3 模板详情 / 编辑页

路径建议：

- `/admin/templates/:id`

用途：

- 查看完整字段
- 编辑模板内容
- 改发布状态
- 改推荐位
- 改排序

### 4.4 导入批次页

路径建议：

- `/admin/templates/import-batches`

用途：

- 看每一批外部模板来源
- 看批次标签
- 看导入时间和数量

## 5. 模板列表页

### 5.1 页面目标

让运营或内容管理员一眼看清：

- 现在有哪些模板
- 哪些已发布
- 哪些是推荐模板
- 哪些来源于哪个仓库
- 哪些还需要整理

### 5.2 页面区块

建议区块：

1. 页面标题区
2. 筛选区
3. 批量操作区
4. 模板表格区
5. 分页区

### 5.3 页面标题区

建议展示：

- 页面标题：`官方模板管理`
- 副标题：说明当前只管理官方模板
- 主按钮：`新建模板`

可选次按钮：

- `导入批次`
- `查看草稿`

### 5.4 筛选区

建议筛选项：

- 关键词搜索
- 分类
- 模板类型
- 发布状态
- 推荐状态
- 来源名
- 导入批次

建议保留排序选项：

- 按更新时间
- 按排序值
- 按创建时间

### 5.5 批量操作区

当选中多条模板时显示：

- 批量发布
- 批量归档
- 批量取消推荐
- 批量设置导入批次

第一版不建议做：

- 批量删除

### 5.6 模板表格区

建议列：

- 选择框
- 标题
- 分类
- 模板类型
- 状态
- 推荐
- 来源
- 排序值
- 更新时间
- 操作

操作列建议：

- 查看 / 编辑
- 发布 / 归档
- 推荐 / 取消推荐

### 5.7 状态展示建议

建议状态标签：

- `草稿`
- `已发布`
- `已归档`

模板类型标签：

- `展示型`
- `可复用`
- `结构化`

## 6. 新建模板页

### 6.1 页面目标

让管理员能够手工录入一条官方模板，并先保存为草稿。

### 6.2 建议表单分组

1. 基础信息
2. Prompt 内容
3. 分类与标签
4. 展示与运营
5. 来源信息

### 6.3 基础信息

字段建议：

- 标题
- slug
- 摘要
- 分类
- 推荐比例

### 6.4 Prompt 内容

字段建议：

- 主提示词
- 负面提示词
- 使用建议

其中 `使用建议` 建议支持多条输入。

### 6.5 分类与标签

字段建议：

- 模板类型
- 标签

### 6.6 展示与运营

字段建议：

- 状态
- 是否推荐
- 排序值
- coverStyle

### 6.7 来源信息

字段建议：

- 来源名
- 作者
- 来源链接
- license
- 导入批次

### 6.8 页面操作按钮

建议按钮：

- 保存草稿
- 保存并发布
- 取消返回

## 7. 模板详情 / 编辑页

### 7.1 页面目标

让管理员在一页内完成：

- 看完整内容
- 编辑内容
- 改状态
- 改推荐位
- 改排序
- 看来源

### 7.2 页面布局建议

建议双栏或三区布局：

1. 左侧主编辑区
2. 右侧运营信息区
3. 顶部页面操作区

### 7.3 顶部页面操作区

建议内容：

- 模板标题
- 当前状态
- 更新时间
- 发布 / 归档按钮
- 保存按钮

### 7.4 左侧主编辑区

建议内容：

- 基础信息表单
- Prompt 表单
- 使用建议表单
- 标签与分类

### 7.5 右侧运营信息区

建议内容：

- 模板类型
- 推荐状态
- 排序值
- 来源信息
- 导入批次
- 使用次数
- 收藏次数

### 7.6 可选只读模块

如果第一版不麻烦，可以加：

- 审计摘要
- 发布时间
- 创建时间

## 8. 导入批次页

### 8.1 页面目标

帮助团队追踪：

- 哪些模板是哪一批导入的
- 每一批来自哪个外部来源
- 当前批次是否已整理完

### 8.2 页面区块

建议区块：

1. 批次列表
2. 批次详情抽屉或详情页

### 8.3 批次列表字段

建议字段：

- 批次名
- 来源名
- 模板数量
- 创建时间
- 操作人
- 备注

### 8.4 第一版边界

第一版不一定要支持真正文件导入，只要支持：

- 记录批次
- 关联模板

就够用。

## 9. 页面间跳转关系

建议主流程：

1. 模板列表页
2. 进入新建模板页或详情页
3. 保存后回列表
4. 从列表进入导入批次页查看来源分布

建议次流程：

1. 列表筛选某来源
2. 进入详情页修正来源或标签
3. 返回列表继续批量整理

## 10. 第一版最小可用组合

如果后台开发时需要压缩范围，第一版最小可用组合建议是：

1. 模板列表页
2. 模板详情 / 编辑页
3. 新建模板页

只要这三页具备，就已经能支撑：

- 官方模板录入
- 编辑
- 上下架
- 推荐位
- 排序管理

导入批次页可以放在后续小版本补。

## 11. 不建议第一版做的页面

第一版不建议做：

- 模板版本对比页
- 模板审核工作流页
- 用户模板后台页
- 模板数据分析大盘
- 模板评论管理页

## 12. 与前台的衔接

后台页面的目标不是替代前台模板库，而是治理前台所用的官方模板数据。

前台未来应逐步变成：

- 读取已发布模板
- 读取推荐模板
- 读取分类与标签

后台则负责：

- 编辑
- 上下架
- 排序
- 来源治理
