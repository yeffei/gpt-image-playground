# 全站 UI 巡检与商业化平台改造批次

日期：2026-07-07

## 当前目标

把全站视觉从早期 `个人版 V1 / 轻量 Apple 玻璃风` 收口到 `标准版 / 商业化图像创作平台`。

新的视觉方向是：专业创作平台里的品牌级控制台。界面要克制、清晰、可长期使用，有品牌感但不软、不甜、不像个人 iOS 工具。

同时要明确抛弃“AI 味”：不使用模板化的紫蓝渐变、漂浮玻璃卡、过度圆角、空泛大标题、假高级光效、同质化卡片堆叠和没有产品语义的装饰元素。界面要像真实团队打磨过的商业软件，而不是 AI 默认生成的漂亮壳。

## 已确认约束

- 不继续沿用现在偏个人工具的 Apple 风、玻璃感、柔雾背景、大圆角漂浮卡片。
- 不保留常见 AI 生成网页味：紫蓝渐变大背景、玻璃拟态卡片、空洞 hero 话术、泛用 bento 卡片、装饰光斑、没有信息用途的图标和标签。
- 不做炫技动效，动效只服务状态反馈、焦点引导、切换连续性。
- 不做营销 landing page，首屏优先是可用的生产与管理体验。
- 前台、Agent 工作台、作品库、提示词库、灵感广场、后台要统一为同一平台气质。
- 架构和模块设计确认前，只做文档讨论和设计沉淀，不直接改 UI 代码。

## 巡检结论

### 全局样式源头

主要问题集中在 `src/index.css`：

- 大量 `backdrop-filter`、半透明白底、柔雾渐变、紫蓝高光和重阴影，直接定义了旧 V1 玻璃系统。
- `--studio-panel`、`--studio-glass`、`--studio-panel-shadow`、`--studio-accent-soft` 等 token 仍服务个人轻量工作台。
- `docs/v1-style-baseline.md` 明确要求“frosted light card / large rounded glass panels”，与当前商业化平台方向冲突。该文档应保留为历史基线，不再作为新 UI 依据。

### 页面级问题

`工作台 / App shell`

- 旧式柔和背景、漂浮面板、胶囊导航仍是第一视觉信号。
- 主生成区信息密度偏个人创作工具，不够像商业平台入口。
- 顶部/侧边导航与各子页面的操作区语言没有形成统一控制台规则。

`AgentWorkflowView`

- 功能已经更接近商业创作流，但视觉仍有大量 panel/card/badge 混用。
- 资产抽屉、路线、时间线、评审、配方、输出阶段的信息密度较高，需要统一成生产控制台结构。
- 适合作为商业化平台 UI 第一批主样板。

`LibraryView`

- 作品库仍偏轻卡片流，适合个人相册，不够像资产管理。
- 筛选、批量管理、状态、回收站、归档之间需要更强的运营管理层级。
- 输出卡片应从“漂亮结果卡”转向“资产项 + 状态 + 操作”。

`PromptLibraryView`

- 卡片、预览、分类、按钮仍有明显柔和玻璃和 marketplace 感。
- 需要转为“官方资产库 / 配方模板库”的信息架构：分类、来源、适用场景、规格、使用行为更清晰。

`InspirationView / InspirationPostView`

- 公开展示属性仍需要保留，但要避免社媒画廊感过强。
- 应定位为平台公开案例库：更多作品状态、来源、入工作台路径、可复用模板入口。

`PlanAndBillingView / RechargeAndResultView`

- 当前充值和额度页视觉偏温和卡片，商业可信度还不够。
- 需要更像结算与账务控制台：金额、流水、规则、状态、失败恢复要更清楚。

`AuthView / SettingsModal / SizePickerModal / PromptOptimizerModal`

- 弹窗和登录仍大量使用大圆角、白玻璃、轻阴影。
- 需要统一到平台级表单和对话框规范：更低圆角、更清晰边界、更稳定输入状态。

`AdminApp`

- 后台已经比前台更接近业务控制台，但与前台视觉割裂。
- 应作为“商业平台密度和表格规则”的参考反向统一前台，不是单独一套后台风格。

## 新设计系统方向

### 视觉 thesis

专业创作平台里的品牌级控制台。

关键词：克制、清晰、运营化、资产化、稳定、可扫描、可长期使用。

反关键词：AI 味、模板味、炫技感、个人玩具感、空泛高级感。

### Token 改造方向

- 背景：从柔雾渐变改为低饱和平台底色，可有非常轻的结构化分区，不使用装饰性光斑。
- Surface：从半透明玻璃改为实色或近实色面板，边界清楚，阴影更轻。
- 圆角：页面级容器控制在 12-16px，卡片和工具面板 8-12px，按钮 8-10px，避免 24-32px 大圆角泛滥。
- 色彩：减少紫蓝渐变主导，建立中性底色 + 单一品牌主色 + 状态色体系。
- 字体：保留中文可读性，减少过度 display 化；标题更像平台模块标题，不像营销标题。
- 动效：保留 hover/focus/active/loading 的必要反馈，不做漂浮卡片动效。

### 组件规则

- 页面结构优先使用 `shell / toolbar / content / inspector / drawer`，减少无意义卡片嵌套。
- 搜索、筛选、分页、tabs、状态 badge、批量操作应统一高度、边界、焦点态。
- 表单必须保留可见 label、helper、error、disabled、loading 状态。
- 资产卡不再只展示图片和按钮，要展示状态、来源、归属、规格、下一步。
- 后台和前台共享同一套状态色语义：active、archived、deleted、failed、recoverable、pending、ready。
- 所有装饰元素必须有产品语义：能解释层级、状态、来源、进度、风险或操作，不做单纯“好看”的背景形状。
- 所有页面文案必须具体，禁止 AI 自己补的抽象标语式说明；优先说清用户正在管理什么、下一步能做什么、系统状态是什么。

## 改造批次

### Batch 0：设计系统基础收口

目标：先建立新商业平台 UI token，不直接重做页面。

范围：

- `src/index.css`
- 全局基础变量、背景、surface、radius、shadow、focus ring、scrollbar
- 兼容旧 class 的过渡 token

交付：

- 新增或替换 `--platform-*` token。
- 标记旧 `--studio-glass*`、大圆角、重玻璃阴影为迁移对象。
- 保证旧页面不崩，再进入页面级改造。

验收：

- 首页背景不再是紫蓝柔雾玻璃。
- 卡片/按钮整体半径明显收敛。
- 旧页面可以继续运行。

### Batch 1：App Shell 与主工作台

目标：先改变第一印象，移除个人工具感。

范围：

- `src/App.tsx`
- `src/index.css`
- 主工作台相关区域、导航、输入面板、结果区域、任务卡基础样式

交付：

- 侧边/顶部导航改为平台控制台导航。
- 主工作台改为生产入口布局：输入、参数、结果、账户状态更清晰。
- 任务卡从漂浮玻璃卡改为资产卡样式。

验收：

- 打开应用第一屏像商业图像平台，而不是本地个人生成器。
- 登录/未登录状态在同一平台壳内自然呈现。

### Batch 2：Agent 工作台作为主样板

目标：把 Agent 工作台做成全站最高优先级的商业创作流样板。

范围：

- `src/components/AgentWorkflowView.tsx`
- `src/components/AgentWorkflowView.css`

交付：

- 统一路线、执行、结果、资产抽屉、配方、评审模块的面板语言。
- 减少 badge/card 杂糅，建立明确分区和操作优先级。
- 资产抽屉适配刚完成的分页、归档、软删除策略。

验收：

- 用户能清楚区分路线规划、执行状态、结果评审、资产管理。
- 失败恢复和资产下一步不被视觉噪声淹没。

### Batch 3：作品库与提示词库资产化

目标：把作品库和提示词库从“浏览卡片”转为“资产库”。

范围：

- `src/components/LibraryView.tsx`
- `src/components/LibraryView.css`
- `src/components/PromptLibraryView.tsx`
- `src/components/PromptLibraryView.css`
- `src/components/TaskCard.tsx`

交付：

- 作品库：强化筛选、状态、批量/回收站、来源、规格、操作。
- 提示词库：强化分类、用途、来源、规格、复用入口，减少 marketplace 装饰感。
- 统一分页、空状态、locked 状态。

验收：

- 作品库像资产管理，不像个人相册。
- 提示词库像官方平台资源库，不像模板展示页。

### Batch 4：灵感广场公开案例库

目标：保留公开浏览能力，但改为平台案例库。

范围：

- `src/components/InspirationView.tsx`
- `src/components/InspirationLatestView.tsx`
- `src/components/InspirationTopicView.tsx`
- `src/components/InspirationPostView.tsx`
- 对应 CSS/共享组件

交付：

- 首页/专题/详情统一为案例库结构。
- 增强“进入工作台 / 复用模板 / 查看来源规格”的平台路径。
- 避免过度社媒瀑布流气质。

验收：

- 公开页面仍可看，但核心导向是平台创作和资产复用。

### Batch 5：账号、充值、设置、弹窗系统

目标：把信任、账务、设置做成商业平台标准表单与对话框。

范围：

- `src/components/AuthView.tsx`
- `src/components/AuthView.css`
- `src/components/PlanAndBillingView.tsx`
- `src/components/PlanAndBillingView.css`
- `src/components/RechargeAndResultView.tsx`
- `src/components/SettingsModal.tsx`
- `src/components/SizePickerModal.tsx`
- `src/components/PromptOptimizerModal.tsx`

交付：

- 登录/注册/恢复：更稳的表单布局和错误状态。
- 充值/额度：账务、价格、流水更像财务控制台。
- 弹窗：统一边界、半径、按钮、焦点、遮罩。

验收：

- 充值和账号页面可信、稳，不像临时个人工具。
- 弹窗视觉不再跳出全站系统。

### Batch 6：后台与前台平台语言统一

目标：后台保持高密度管理能力，同时和前台共享平台视觉语言。

范围：

- `src/components/AdminApp.tsx`
- `src/components/AdminApp.css`

交付：

- 后台表格、筛选、详情、操作面板与前台资产管理共享状态语义。
- 统一按钮、tabs、表单、空状态、错误状态。

验收：

- 前后台像同一套平台的不同权限视图。

### Batch 7：全站 QA 与回归

目标：完成视觉改造后的稳定性验收。

范围：

- 桌面、窄屏、移动端主要页面。
- 登录/未登录、无资产、有资产、失败任务、归档/删除、充值失败/成功等状态。

交付：

- Playwright 截图或人工截图清单。
- 构建和关键测试通过。
- 记录遗留问题和下一轮细化项。

验收：

- 无文字重叠。
- 无按钮文本溢出。
- 无核心内容横向滚动。
- focus/hover/disabled/loading/empty/error 状态可见。

## 优先级建议

第一优先级：

1. Batch 0
2. Batch 1
3. Batch 2

原因：这三批决定用户第一眼是否还觉得是个人 Apple 风工具。

第二优先级：

4. Batch 3
5. Batch 5

原因：资产库、模板库、账务页决定商业平台可信度。

第三优先级：

6. Batch 4
7. Batch 6
8. Batch 7

原因：公开案例和后台统一重要，但应在主工作台和资产库语言稳定后推进。

## 不做清单

- 不新增暗黑主题作为这轮目标。
- 不用大面积紫蓝渐变制造高级感。
- 不用大圆角白玻璃卡片继续堆页面。
- 不用 AI 默认审美：渐变光斑、过度 bento、无语义插画、空泛 slogan、每块都像展示卡。
- 不把页面改成营销站 hero。
- 不先重构业务逻辑，UI 改造只围绕现有功能和已确认产品主线。

## 反 AI 味验收标准

每个批次完成后必须额外检查：

- 如果去掉所有真实业务数据，页面是否仍像模板站？如果像，说明还不够产品化。
- 是否存在只为装饰而存在的渐变、光斑、玻璃、图标、空卡片？有则移除或改成有状态语义的组件。
- 页面标题和说明是否能替换到任意 AI 产品上仍成立？如果成立，说明文案太空。
- 卡片是否只是“图片 + 标题 + 按钮”的重复网格？如果是，需要补资产状态、来源、规格、操作层级。
- 主色是否被紫蓝渐变支配？如果是，需要回到中性平台底色和克制品牌色。
- 是否每个区域都在争夺视觉焦点？如果是，需要降低装饰强度，恢复操作优先级。

## 下一步

建议从 Batch 0 开始，先改 `src/index.css` 的全局 token 和旧玻璃风兼容层。确认全局基调后，再进入 Batch 1 主工作台和导航。
