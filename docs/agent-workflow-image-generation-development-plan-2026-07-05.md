# 智能创作流开发计划

更新时间：2026-07-05

适用范围：`D:\gpt_image_playground-main`

## 1. 核心判断

平台功能已经接近完整生图工具形态，下一阶段不应只增加一个“Agent 按钮”，而应把平台升级为：

> 商业化图像创作平台里的智能创作流系统。

这里的 Agent 不是开放式聊天机器人，也不是无限自治任务执行器，而是围绕商业图像生产的可控工作流：

- 用户输入模糊需求。
- 平台生成结构化 Brief。
- 平台推荐分类、提示词、比例、模型、线路、张数和预计消耗。
- 用户确认后执行生成。
- 结果沉淀为配方、历史和后续可复用资产。

一期前台建议使用名称：`智能创作流`。

后台和技术文档中可以使用名称：`Agent Workflow`。

## 2. 外部开源项目学习结论

本阶段调研的重点不是直接复制某个仓库，而是提炼适合本平台商业化主线的设计原则。

### 2.1 ComfyUI

可学习点：

- 节点图和工作流可保存。
- 复杂能力可以封装为用户可执行模板。
- 底层复杂，前台可以通过简化模式暴露给普通用户。
- 工作流模板本身可以成为平台资产。

不建议直接照搬：

- 一期不做自由节点编辑器。
- 不把复杂参数暴露给普通用户作为主流程。

### 2.2 InvokeAI

可学习点：

- 生成不是终点，精修、迭代、版本管理才是专业创作流程。
- 平台需要沉淀资产，而不是只返回单张结果。

### 2.3 Fooocus

可学习点：

- 普通用户更需要隐藏复杂度。
- Prompt expansion、style preset、质量词自动补充很适合前台轻量化。
- 用户只需要关心目标和结果，高级参数可以折叠。

### 2.4 AUTOMATIC1111 Stable Diffusion WebUI

可学习点：

- txt2img、img2img、inpainting、outpainting、upscale、插件生态都说明高级能力应模块化。
- 高级能力不应全部塞进单一主流程。

### 2.5 Vibe Workflow / Open AI Design Agent

可学习点：

- brief -> plan -> generate -> edit -> assemble 是适合商业创作的链路。
- Agent 的核心价值是创作规划、多资产组合和模型路由，而不是单张图提示词扩写。
- 每个计划、模型选择和费用应可见可改。

### 2.6 LangGraph 类状态化 Agent 框架

可学习点：

- Agent 流必须有状态机。
- 长任务需要可恢复、可观察、可中止。
- human-in-the-loop 比完全自治更适合商业扣费场景。

## 3. 产品定位

一期产品定位：

> 智能创作流帮用户把模糊需求变成可执行的商业图像生成方案，并用可控成本生成多版结果。

核心价值：

- 降低提示词门槛。
- 提升首次可用图概率。
- 让扣费前的方案更透明。
- 让生成结果可继续复用。
- 为后续图像配方、项目制创作、品牌记忆打基础。

## 4. 一期 MVP 范围

一期只做一个主入口：

> 智能创作流。

固定流程：

```txt
1. 需求理解
2. Brief 结构化
3. 提示词增强
4. 模型与参数推荐
5. 用户确认费用
6. 多图生成
7. 结果整理与后续操作
```

一期不做：

- 自由节点编辑器。
- 无限自动重试。
- 自动连续扣费。
- 复杂图像评分。
- 多人协作。
- 完整品牌资产系统。
- 大型项目管理系统。
- 开放式 Agent 聊天执行器。

## 5. 产品模块

### 5.1 智能创作入口

用户输入一句自然语言需求，例如：

```txt
给一款低糖柠檬气泡水做一张夏季小红书推广图
```

入口可支持：

- 大输入框。
- 参考图上传入口。
- 用途快捷选项。
- 生成 Brief 按钮。

### 5.2 创作 Brief 卡

Brief 卡是一期核心，不是装饰 UI。

示例结构：

```txt
创作用途：小红书推广图
图像类型：品牌广告
主体：低糖柠檬气泡水
推荐比例：4:5
推荐风格：清爽产品摄影、明亮商业广告
建议元素：瓶身、冰块、柠檬片、水花、夏季阳光
推荐生成数量：4 张
预计消耗：X 点余额
建议：上传产品参考图
```

Brief 卡承担的职责：

- 帮用户确认需求。
- 解释平台准备如何生成。
- 明确预计消耗。
- 给后续工作流提供结构化输入。
- 在扣费前提供最后确认点。

### 5.3 提示词增强

一期基于现有 `src/lib/promptLibrary.ts` 分类体系增强：

- `海报插画`
- `人像摄影`
- `产品静物`
- `空间氛围`
- `品牌广告`
- `UI / 社媒视觉`
- `角色设定`
- `信息图解`

一期能力范围：

- 意图分类。
- 模板增强。
- 质量词补充。
- 场景、镜头、材质、光线补充。
- 负面词生成。
- 比例建议。

### 5.4 模型与线路推荐

一期先做规则驱动，不急于上复杂 Agent 决策。

示例规则：

```txt
品牌广告 -> 商业质感模型 / 高质量线路
产品静物 -> 产品摄影线路
人像摄影 -> 真人质感线路
UI / 社媒视觉 -> 适合文字和界面结构的线路
信息图解 -> 清晰排版优先线路
角色设定 -> 角色一致性优先线路
空间氛围 -> 场景构图和光影优先线路
```

### 5.5 生成确认页

生成前必须展示：

- 生成数量。
- 使用模型 / 线路。
- 图片比例。
- 预计消耗。
- 是否使用参考图。
- 是否保存为配方。

用户确认后才进入扣费和执行。

### 5.6 结果页

每张图下方提供后续动作：

- 同风格再生成。
- 改成电商主图。
- 改成小红书封面。
- 改成横版海报。
- 高清放大。
- 保存为配方。
- 复制提示词。

结果页目标：

- 不让图片生成后流程中断。
- 鼓励用户继续创作。
- 将成功结果沉淀为可复用资产。

## 6. 后端模块规划

建议新增核心概念：

```txt
agent_runs
agent_steps
agent_step_outputs
image_recipes
model_invocations
balance_transactions
```

一期最重要的是：

- `agent_runs`
- `agent_steps`

### 6.1 agent_runs

记录一次智能创作流。

建议字段：

```txt
id
user_id
status
original_input
brief_json
final_prompt
negative_prompt
category
model_id
route_id
aspect_ratio
image_count
estimated_cost
actual_cost
created_at
updated_at
```

### 6.2 agent_steps

记录每一步执行状态。

建议字段：

```txt
id
run_id
step_type
status
input_json
output_json
cost
error_message
started_at
finished_at
```

### 6.3 状态机

建议状态：

```txt
draft
planned
confirmed
running
succeeded
failed
canceled
```

含义：

- `draft`：用户刚输入需求，尚未形成方案。
- `planned`：已生成 Brief 和预计消耗。
- `confirmed`：用户已确认方案。
- `running`：正在执行生成。
- `succeeded`：流程成功完成。
- `failed`：流程失败。
- `canceled`：用户取消或系统取消。

## 7. API 规划

一期 API 可以按以下顺序设计。

### 7.1 生成计划

```txt
POST /api/agent-runs/plan
```

职责：

- 接收用户原始需求。
- 生成结构化 Brief。
- 输出推荐分类、提示词、负面词、比例、张数、模型、线路、预计消耗。
- 创建 `agent_runs` 记录，状态进入 `planned`。

### 7.2 确认方案

```txt
POST /api/agent-runs/:id/confirm
```

职责：

- 锁定用户确认后的 Brief 和参数。
- 检查余额是否足够。
- 状态进入 `confirmed`。

### 7.3 开始执行

```txt
POST /api/agent-runs/:id/start
```

职责：

- 状态进入 `running`。
- 调用现有生图能力。
- 写入 `agent_steps`。
- 写入模型调用记录和余额流水。

### 7.4 查询状态

```txt
GET /api/agent-runs/:id
```

职责：

- 返回运行状态。
- 返回步骤记录。
- 返回结果图片。
- 返回费用信息和失败原因。

### 7.5 重试

```txt
POST /api/agent-runs/:id/retry
```

职责：

- 支持失败后重试指定步骤或整次任务。
- 重试前必须重新确认预计消耗。

### 7.6 保存图像配方

```txt
POST /api/image-recipes
```

职责：

- 保存成功图片的生成配方。
- 记录提示词、负面词、模型、线路、比例、种子、参考图和后处理步骤。

## 9. 开发阶段

### 阶段 1：现状梳理

目标：

- 确认现有生成 API。
- 确认余额扣费逻辑。
- 确认模型 / 线路配置方式。
- 确认历史记录结构。
- 确认前台页面结构。

产出：

```txt
现有能力映射
可复用模块清单
需要新增的数据表和 API 清单
```

### 阶段 2：数据结构与状态机

目标：

- 建立 `agent_runs`。
- 建立 `agent_steps`。
- 打通状态流转。
- 不接真实生成也能跑通流程。

验收：

```txt
用户输入 -> plan -> confirm -> running -> succeeded / failed
```

### 阶段 3：Brief 与提示词增强

目标：

- 基于分类规则生成 Brief。
- 基于提示词库生成增强提示词。
- 输出结构化参数。

验收：

```txt
同一句需求可以稳定生成分类、用途、比例、提示词、预计张数
```

### 阶段 4：接入真实生成链路

目标：

- 调用现有生图能力。
- 记录每次模型调用。
- 接入余额预估和实际扣费。
- 失败时记录原因。

验收：

```txt
智能创作流能真实生成多张图，并正确记录费用和结果
```

### 阶段 5：结果页与配方

目标：

- 图片结果关联 `agent_run`。
- 支持保存为图像配方。
- 支持复制提示词。
- 支持同风格再生成。

验收：

```txt
用户可以从一张结果图继续创作，而不是流程结束即断掉
```

### 阶段 6：灰度与指标

目标：

- 只对管理员或部分用户开放。
- 记录使用率、下载率、保存配方率、失败率、平均消耗。

关键指标：

```txt
智能创作流使用率
生成成功率
图片下载率
配方保存率
单次创作平均消耗
失败退款 / 投诉情况
```

## 11. 成本与扣费原则

智能创作流必须遵守以下原则：

- 扣费前展示预计消耗。
- 用户确认后才执行真实生成。
- 不做无限自动扣费。
- 每一步真实模型调用都要记录。
- 失败要记录失败原因。
- 重试前重新展示成本。
- 后续如果加入自动精修，必须作为单独确认步骤。

## 12. 成功标准

一期成功标准不是“Agent 多聪明”，而是：

> 用户更容易开始创作，生成过程更可控，结果更容易继续复用，平台能沉淀可计费的创作资产。

具体指标：

- 智能创作流使用率提升。
- 智能创作流图片下载率高于普通生成。
- 用户反复乱改提示词的次数下降。
- 配方保存率有明显占比。
- 单次创作平均消耗提升，但投诉不增加。
- 失败链路可追踪、可解释、可处理。

## 13. 后续演进方向

一期跑通后，再考虑以下方向：

- 图像配方库。
- 项目制创作。
- 品牌记忆。
- 审美 / 商业可用性评分。
- 失败图复盘。
- 批量变体导演。
- Campaign 多资产生成。
- 更细粒度的模型路由。
- 工作流模板后台管理。

其中最推荐的中期组合：

```txt
项目制创作 + 品牌记忆 + 图像配方 + 可控 Agent 工作流
```

这条路线能把平台从“生成工具”升级为“商业图像创作系统”。
