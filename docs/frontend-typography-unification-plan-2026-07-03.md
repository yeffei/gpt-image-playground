# 前台字体统一方案

日期：2026-07-03  
适用范围：`D:\gpt_image_playground-main` 前台页面  
时区：`Asia/Shanghai`

## 1. 当前目标

把前台页面的字体体验从“局部好看、全站不统一”整理成一套稳定可复用的字体系统，优先解决：

1. 元信息、按钮、标签字号过小
2. 中文标题负字距过重
3. 页面之间标题层级比例不一致
4. `src/index.css` 与各页面样式里存在多轮覆盖，导致字号口径漂移

本轮先做方案沉淀，不直接改视觉实现。

---

## 2. 当前审查结论

### 2.1 不是字体文件坏了，而是规则体系混乱

当前前台全局字体栈本身可用：

- `Avenir Next`
- `SF Pro Display`
- `HarmonyOS Sans SC`
- `PingFang SC`
- `Microsoft YaHei`
- `Noto Sans SC`

问题不在“有没有字体”，而在：

1. 中文、英文、数字混排时气质不完全统一
2. 大量 `9px ~ 10px` 文本出现在真实业务界面
3. 多个页面各自定义标题比例，没有共享一套层级
4. 同一个组件在 `index.css` 里被多次覆盖，最终效果依赖覆盖顺序

### 2.2 当前最明显的别扭来源

#### A. 太多小字

当前前台里很多 secondary / meta / chip / button 文本落在：

- `9px`
- `9.5px`
- `10px`
- `10.5px`

这些值在桌面中文产品界面里过密、过轻，容易出现：

1. 看起来像缩小版原型
2. 信息层级不是“次要”，而是“难读”
3. 同一块卡片里标题正常，下面一排字突然变得发虚

#### B. 中文标题负字距过多

当前多个页面标题在用：

- `letter-spacing: -0.03em`
- `letter-spacing: -0.04em`
- `tracking-[-0.04em]`
- `tracking-[-0.05em]`

短英文标题有时成立，但中文标题普遍会显得：

1. 笔画拥挤
2. 视觉发闷
3. 页面一多之后“都很用力”

#### C. 页面级比例不统一

例如：

- 提示词库主标题比作品库明显大
- 收藏区标题又比主页面标题小很多
- 顶部胶囊、页脚、卡片按钮都各有一套细碎字号

结果是单页内部可能还行，但页面切换时会觉得不像同一个产品体系。

#### D. 样式覆盖链太长

当前导航、卡片、工作台等区域有明显的多轮压缩覆盖痕迹。  
这会让后续任何字体微调都变成“局部修一下，别的地方又跑掉”。

## 3. 统一原则

### 3.1 字体方向

前台继续保持：

- 中文优先产品化无衬线
- 英文和数字保持清晰、现代、不过度展示感
- 不引入额外 WebFont，优先用现有系统栈

建议保留现有全局字体栈，但调整使用策略：

1. 页面主标题不再依赖过重字距塑形
2. 数字徽标、点数、标签优先通过字重和容器强化，不靠极小字号
3. 英文 / 数字混排区域尽量减少和中文正文完全不同的视觉节奏

### 3.2 字号下限

前台默认不再把常规可读文本压到 `10px` 以下。  
建议下限：

- `11px`：极次要 meta / badge / kicker 的最低值
- `12px`：按钮、筛选、chip、辅助说明的默认下限
- `13px`：卡片正文摘要、小段说明的常规起点

### 3.3 中文标题规则

建议改成：

1. 中文主标题默认 `letter-spacing: 0` 或轻微负值 `-0.01em`
2. 中文区块标题默认 `0` 或 `-0.01em`
3. 只有极短、偏展示型、英文占比高的标题才允许 `-0.02em ~ -0.03em`
4. 不再把 `-0.04em ~ -0.05em` 当作前台常规标题值

### 3.4 统一层级

建议把前台标题分成四层：

- `Display`
  - 用于灵感广场 / 专题页 hero 级标题
  - 建议 `32px ~ 40px`
- `Page Title`
  - 用于作品库 / 提示词库 / 计划与额度等一级页面标题
  - 建议 `24px ~ 28px`
- `Section Title`
  - 用于卡片组、区块、面板标题
  - 建议 `18px ~ 20px`
- `Card Title`
  - 用于结果卡、模板卡、专题卡
  - 建议 `14px ~ 16px`

辅助层级建议：

- `Body`：`13px ~ 14px`
- `Support`：`12px`
- `Meta`：`11px`
- `Micro`：仅极少数 badge 使用 `11px`，不再常规使用 `9px ~ 10px`

## 4. 拟定前台字体标尺

### 4.1 全局标尺建议

| 层级 | 建议字号 | 建议字重 | 字距建议 | 典型用途 |
| --- | --- | --- | --- | --- |
| Display XL | `clamp(2rem, 3.6vw, 2.75rem)` | `700~780` | `0 ~ -0.02em` | 专题页 / 灵感页主标题 |
| Page L | `26px` | `780~820` | `0 ~ -0.01em` | 页面主标题 |
| Section M | `18px` | `700~780` | `0 ~ -0.01em` | 区块标题 |
| Card M | `15px` | `650~760` | `0` | 卡片标题 |
| Body | `13px` | `400~520` | `0` | 摘要、说明 |
| Support | `12px` | `500~620` | `0 ~ 0.01em` | 辅助说明、工具条 |
| Meta | `11px` | `600~700` | `0.02em` 以内 | badge、标签、统计 |

### 4.2 明确禁止

前台统一时，默认避免：

1. 中文常规文本 `9px`
2. 中文正文或按钮 `10px`
3. 中文主标题 `-0.04em` 及更重负字距
4. 同一块区域标题、说明、按钮跨越过多字号档位

## 5. 第一批需要统一的页面

按优先级分三批推进。

### 第一批：用户最常切换、最容易感到“别扭”的区域

1. 顶部 `Header`
2. 左侧导航
3. 工作台结果区卡片
4. 作品库 / 收藏
5. 提示词库
6. 灵感广场首页
7. 计划与额度

### 第二批：次高频但风格已开始分叉的区域

1. 灵感专题页
2. 设置
3. 帮助
4. 登录 / 注册
5. 收藏区 `CuratedShelf`
6. 页脚

### 第三批：专项体验模块

1. Prompt Optimizer Modal
2. Mask Editor Modal
3. Gateway Diagnostics
4. Toast / ConfirmDialog 等系统反馈组件

## 6. 具体落点建议

### 6.1 `src/index.css`

作为第一优先级处理对象。

目标：

1. 抽出前台统一字体 token 或至少统一变量注释区
2. 收敛导航、顶部栏、工作台卡片这类基础部件的字号
3. 清理多轮覆盖，只保留一套最终值

特别是：

- `prototype-nav-group-title`
- `prototype-nav-label strong`
- `prototype-nav-label small`
- `prototype-topbar`
- `prototype-account-menu-*`
- `prototype-result-card` 相关文字

### 6.2 页面级样式文件

需要逐页统一：

- `src/components/LibraryView.css`
- `src/components/PromptLibraryView.css`
- `src/components/PlanAndBillingView.css`
- `src/components/CuratedShelf.css`
- `src/components/SiteFooter.css`
- `src/components/AuthView.css`

原则不是“每页自成体系”，而是让这些文件服从同一套字号表。

### 6.3 直接写在 JSX className 里的页面

需要重点回收：

- `src/components/InspirationView.tsx`
- `src/components/InspirationTopicView.tsx`
- `src/components/SettingsModal.tsx`
- `src/components/HelpModal.tsx`

这些文件现在直接写了较多 `text-[...]` 和 `tracking-[...]`，后续最好逐步替换为更稳定的组件级 class 或语义 class。

## 7. 建议实施顺序

### Stage A：建立前台字体基线

只处理：

1. 页面主标题
2. 区块标题
3. 常规说明文字
4. 导航和顶部栏

目标是先把“第一眼别扭”消掉。

### Stage B：收敛小字系统

统一：

1. 标签
2. badge
3. 工具条按钮
4. 卡片底部 meta
5. 页脚和说明文案

目标是把 `9px ~ 10px` 文本大幅减少。

### Stage C：清理重复覆盖

重点清理：

1. `index.css` 里的多轮导航覆盖
2. 工作台结果卡多轮压缩覆盖
3. 页面 CSS 与 JSX 内联字号口径不一致的问题

目标是后续改字体时不会牵一发而动全身。

---

## 8. 预期效果

统一完成后，前台应该达到：

1. 页面之间切换时，字号层级明显属于同一家产品
2. 中文标题不再有明显“字挤在一起”的感觉
3. 小字不再发虚，按钮和 meta 信息可读性更稳定
4. 工作台、作品库、提示词库、灵感广场之间气质统一但不呆板
5. 后续继续做视觉抛光时，不需要反复重新校正字体

---

## 9. 下一步执行建议

建议下一轮直接进入 **Stage A**，但依然分两步：

1. 先只改基础标尺：
   - `Header`
   - 左侧导航
   - 页面主标题
   - 区块标题
2. 再改高频页面：
   - 作品库

这样可以先把全站主观“别扭感”快速压下来，再进入细部统一。
