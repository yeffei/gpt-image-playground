# 提示词优化器统一设计

## 目标

把现有两份规则文档：

- `text_to_image_prompt_optimizer.md`
- `image_to_image_prompt_optimizer.md`

收敛成一个真正可接入当前产品的“提示词优化器”能力。

这份设计只定义：

- 什么时候触发 `Text-to-Image` 优化
- 什么时候触发 `Image-to-Image` 优化
- 优化结果输出哪些字段
- 哪些字段回填到当前界面
- 哪些字段只作为辅助展示

本设计面向当前 `V1 / 个人版`，默认保持轻量，不引入复杂工作流。

---

## 一、产品定位

提示词优化器不是新的独立页面，也不是大而全的 AI 助手。

它在当前产品中的定位应该是：

- 一个贴近输入区的小工具
- 用来把“原始想法”整理成“更稳定、可执行的生成提示词”
- 默认服务于单次生成，不抢主流程

所以它应当满足：

- 触发快
- 输出清晰
- 一次点击就能用
- 不强制改用户已有参数

---

## 二、模式判断

系统不需要让用户先选“文生图优化”还是“图生图优化”。

建议由程序自动判断：

### 1. 使用 `Text-to-Image` 优化器

条件：

- 当前没有挂参考图
- 当前没有启用遮罩编辑

即：

- `inputImages.length === 0`
- `maskDraft` 为空

### 2. 使用 `Image-to-Image` 优化器

条件：

- 当前存在至少一张参考图
- 或当前处于遮罩/局部编辑相关场景

即：

- `inputImages.length > 0`
- 或 `maskDraft` 不为空

### 3. 用户感知层面的文案

按钮统一叫：

- `优化提示词`

点击后无需再弹二选一。

结果面板中再标明本次模式：

- `本次优化模式：文生图`
- `本次优化模式：图生图`

---

## 三、统一输入

优化器的输入不应只拿主提示词，还应带上当前上下文，避免“优化后和实际生成参数脱节”。

建议输入上下文包括：

- 原始提示词
- 当前是否有参考图
- 当前是否有遮罩
- 当前尺寸 / 比例
- 当前质量参数
- 当前负面提示词（如果已有）

但第一版真正传给优化器时，可以先只强依赖以下最小集：

- `prompt`
- `hasReferenceImages`
- `hasMask`
- `currentSize`
- `currentNegativePrompt`

---

## 四、统一输出结构

现有两份文档输出项较多。为了适配当前个人版，第一版建议统一成下面这套固定结构。

```text
优化说明
优化后的主提示词
Negative Prompt
推荐比例 / 尺寸
可选增强项
```

### 1. 优化说明

作用：

- 让用户知道这次主要改了什么
- 便于判断优化方向有没有跑偏

要求：

- 1 到 3 条短句
- 不要写成长段解释

### 2. 优化后的主提示词

作用：

- 这是最核心输出
- 也是唯一必须可直接回填并用于生成的内容

要求：

- 输出一版最终可执行提示词
- 默认以英文为主，兼顾模型执行稳定性
- 不再同时强制输出一大段中文+英文双份正文

说明：

- 中文说明可以保留在“优化说明”里
- 主提示词本身优先服务生成效果

### 3. Negative Prompt

作用：

- 单独回填到现有负面提示词输入区

要求：

- 如果用户已有负面提示词，优先做“补充合并”，不要完全覆盖用户原有约束
- 如果用户没有负面提示词，则生成一套默认约束

### 4. 推荐比例 / 尺寸

作用：

- 只给建议，不自动覆盖当前尺寸设置

要求：

- 输出一个建议值即可
- 例如：`9:16`、`1:1`、`1536x1024`

### 5. 可选增强项

作用：

- 作为附加建议显示

内容建议：

- 胶片感
- 抓拍感
- 光线方向
- 镜头感
- 材质真实度

要求：

- 仅展示
- 不自动写入参数

---

## 五、回填规则

这是当前最关键的落地点。

优化结果不要“一股脑全写进主输入框”，必须分清哪些是直接写回，哪些只是展示。

### 1. 主提示词

回填目标：

- 主提示词输入框

规则：

- 用户点击 `应用优化结果` 后，覆盖当前主提示词

### 2. Negative Prompt

回填目标：

- 负面提示词输入框

规则：

- 如果当前负面提示词为空，直接写入
- 如果当前已有内容，建议弹一个轻量二选一：
  - `替换`
  - `追加合并`

第一版也可以先简化为：

- 默认追加合并

### 3. 推荐比例 / 尺寸

回填目标：

- 不自动回填

规则：

- 只展示为建议
- 用户自己决定是否改当前尺寸参数

### 4. 可选增强项

回填目标：

- 不自动回填

规则：

- 只做辅助显示

---

## 六、界面接入建议

### 方案

不新开页面，直接接在当前输入区附近。

建议位置：

- 主输入框右侧或下方
- 与“生成”动作保持邻近

建议按钮：

- `优化提示词`

点击后行为：

1. 打开一个轻量结果面板或弹层
2. 展示统一输出结构
3. 提供两个动作按钮：
   - `应用优化结果`
   - `仅复制`

### 不建议的做法

- 不建议单独做一个“大型提示词实验室”页面
- 不建议第一版就加入多轮对话式优化
- 不建议让用户先手动选 T2I / I2I

---

## 七、两种模式的差异保留方式

虽然产品上统一成一个入口，但底层规则仍然应该保留两套。

### 1. `Text-to-Image` 规则重点

- 强化从抽象描述到具体视觉描述
- 更强调完整构图建立
- 允许补全更多场景元素

### 2. `Image-to-Image` 规则重点

- 严格保留原图主体与场景方向
- 少做结构性改写
- 强调“增强”和“控制”，而不是“重写”

### 3. 实现层建议

保留两份底层提示词模板：

- `prompt optimizer / t2i`
- `prompt optimizer / i2i`

统一由一个产品入口调度。

---

## 八、第一版最小可用范围

建议第一版只做以下能力：

- 一个入口：`优化提示词`
- 自动判断 T2I / I2I
- 输出：
  - 优化说明
  - 优化后的主提示词
  - Negative Prompt
  - 推荐比例
- 支持：
  - 应用结果
  - 复制结果

先不做：

- 历史优化记录
- 多版本对比
- 一键覆盖尺寸参数
- 模板化风格推荐
- 提示词评分系统

---

## 九、后续可扩展方向

如果第一版效果稳定，后续可以再加：

- `轻优化 / 强优化` 两档
- 保守模式 / 创意模式
- 保留人物构图优先级
- 自动识别电商图 / 人像 / 空间 / 海报场景
- 与提示词模板库联动

---

## 十、结论

后续不应把这两个 `md` 当作静态文档继续堆放。

正确做法是：

- 保留两套底层优化规则
- 产品层统一成一个 `优化提示词` 入口
- 第一版只输出最有价值的少数字段
- 只回填主提示词和负面提示词
- 推荐比例和增强项只展示，不自动改用户当前设置

这样最符合当前个人版的轻量定位，也最容易后面继续扩成网站版能力。
